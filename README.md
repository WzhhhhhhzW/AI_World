# 谷言 · 一座会思考的村庄

独立的像素村庄原型：居民在村间走路、采集材料、合力建设；你可给每位居民分配不同模型服务，召集会议并查看实际 Token 账本。旧横版游戏和已通过本地核心验收的内核交付包均未改动。

## 菜园委托与铁匠铺

打开地图下方的 **委托田 → 播下委托**，选择技艺和一位主理人。也可以在现有居民聊天里点击 **转为协作委托**，把输入框里尚未发送的文字带入委托表单，预选这位居民为主理人。菜园建成后即可继续填写，完成表单后由玩家提交。第一次可选「本地实习」和「村务盘点」，按技艺允许的数据项生成盘点单。本地实习使用确定性规则，无需配置模型。

选择「真实模型」后，主理人先独立处理委托。一份顺利交付的委托只调用主理人一次。遇到卡点时，你可以自己补充条件，也可以每稿依次邀请最多三位不同的居民独立判断。每位顾问收到原题、你指定的问题和本稿的允许材料快照。页面按顾问分组展示建议，初始均为空选。你可从各组勾选最多三条，确认后随你的补充一并交回主理人。每份委托最多保留三版主稿。「委托案卷」可以对照各稿和建议采纳记录，下载工作记录。

工坊落成后，点开 **工坊 → 铁匠铺**，把一套方法写成技能，指定工作步骤和允许读取的村务材料。纯文字委托可将材料留空。已收获的成果也可以点「锻造成技艺」，整理后收入技艺册。展开技艺卡的「查看 SKILL.md」即可读到完整 Markdown，常规浏览器可下载同一份内容。原有的播种、施工、议事和粮仓操作可从地图照常进入。

## 运行

本机已准备好竞赛演示所需内核和运行盘时，双击 **启动赛题村庄.cmd**。它通过 WSL Ubuntu 打开 QEMU 的图形窗口，随后在客体 Chromium 内加载村庄。首次进入要等 Weston 桌面与浏览器先后出现。此入口的村庄保存在宿主 Ubuntu 用户的 `~/.local/share/qilin-village/village.json`，可在地图下方点击「委托田」开始试玩。[赛题平台运行说明](platform/README.md) · [客体实测记录](platform/evidence/run.json)

双击本目录的 **启动游戏.cmd**。它会启动本机服务并自动打开村庄；已经启动时会复用同一服务。优先使用本机已有的 Codex Python，也支持系统 Python 3.10+，没有第三方依赖。

也可在本目录运行：

```powershell
python server.py
```

或者运行 `start.ps1`。浏览器地址为 **http://127.0.0.1:8766/**。从游戏「设置」里的「保存并退出村庄」正常退出，也可在服务窗口按 Ctrl+C。默认只监听本机；存档在 `data/village.json`，重启后保留居民、建设、记忆、议题和账本。直接打开 `web/index.html` 会显示启动引导，不再显示缺少素材和居民的半成品地图。正常入口等待地图、人物、UI与存档全部就绪后才进入游戏。

## 当前可用内容

- 三位初始居民，也能创建新居民，设置姓名、职业、性格、模型服务和预算；最多 12 位。
- 创建时可从用户提供的 ChatGPT、Claude、Grok、DeepSeek、Gemini、豆包六款外观中选择，外观独立于API服务保存；地图与资料头像使用同一选择。旧存档自动补全外观而不重置预算。当前仅有正面静态立绘，后续动画规格见 `村民动态形象美术要求.md`。
- 本地确定性日常：居民错开工作站位，采集后携带木石或作物走到粮仓，入库后短暂停歇，再返回工作地点；资源实际送达才增加。新村庄自带菜园，旧存档保留原建设进度；工坊、档案馆等由居民实际走到工地施工。
- 场景细节：水纹流动和闪光、树木与作物轻摆、落叶、蝴蝶、烟囱烟气、脚步扬尘、工作碎屑，以及随村庄时间变化的暮色、窗灯与萤火虫。暂停村庄也会冻结环境动画。人物使用现有正面立绘的呼吸与行走摆动，完整四向逐帧动画仍按人物素材规格补充。
- 地图可按住拖动、用滚轮或右下角加减号缩放；小房子按钮恢复全村视角。窄窗口默认放大，避免人物缩成难以辨认的小点。
- 真实模型生活决策：居民读取自己的有限记忆与村庄资源，从采木/采石/园艺/建设中选择行动，程序校验后执行。无 API 时不会伪造模型决策。
- 会议：保存议题 → 选 1–6 位已配置居民 → 走到议事厅 → 各自独立提案 → 首位居民作为主持人读取全部提案并汇总。共 **N+1 次真实调用**；没有伪称已实现额外多轮辩论。中途失败保留已有发言。
- 粮仓：每位居民的分配/实际消耗/预留/可用额度，逐次记录输入、输出、合计和模型。拨粮只是增加本地调用预算，不是服务商充值或余额同步。
- 档案馆：会议与居民记忆、模型配置状态；页面刷新和服务重启后保留。
- 自主思考默认关闭；开启后每 120 秒轮到一位已配置居民做一次决策。当前任务串行执行；重启后恢复关闭。
- 本地日常不会消耗 Token，也不是离线大模型推理。施工、走路等不用每帧调用 API。

## 连接模型

在村庄中点击居民，打开「API 接入设置」。选择模型服务，填写控制台中的模型 ID（豆包也可填写接入点 ID）与 API Key，保存后即可在这位居民的资料里点击「让 TA 想一想」。会议发言和投票同样使用这位居民的配置。

专用密钥由本机服务保存，位于存档旁的私有目录。在 Windows 上使用当前账户的 DPAPI 加密。修改同一服务、同一地址的模型时可以留空沿用密钥。换服务或地址时需填写相应密钥。

「使用本机默认设置」适合多位居民共用同一服务配置。默认模型和密钥采用下表中的环境变量。

| 服务 | 密钥环境变量 | 模型环境变量 | 默认 Base URL |
|---|---|---|---|
| DeepSeek | `DEEPSEEK_API_KEY` | `DEEPSEEK_MODEL` | `https://api.deepseek.com` |
| 豆包 / 方舟 | `ARK_API_KEY` | `ARK_MODEL` | `https://ark.cn-beijing.volces.com/api/v3` |
| 千问 / 百炼 | `DASHSCOPE_API_KEY` | `QWEN_MODEL` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 混元 / 腾讯云 | `HUNYUAN_API_KEY` | `HUNYUAN_MODEL` | `https://tokenhub.tencentmaas.com/v1` |
| 其他兼容接口 | `VILLAGE_API_KEY` | `VILLAGE_MODEL` | 需自行配置 |

在启动服务前设置对应环境变量即可。值只保存在你本机；不要把含真实密钥的命令截屏、提交或分享。服务重启后重新读取配置。页面的“已配置”仅表示配置存在，不表示真实连通性已验证；首次点击居民“让 TA 想一想”才会实际调用。

如要修改端点，复制 `providers.example.json` 为 `providers.local.json`，修改 `base_url`，保留密钥环境变量名。服务自动追加 `/chat/completions`，**不要把完整接口路径填成 Base URL**。也可用 `VILLAGE_DEEPSEEK_BASE_URL`、`VILLAGE_DOUBAO_BASE_URL`、`VILLAGE_QWEN_BASE_URL`、`VILLAGE_HUNYUAN_BASE_URL`、`VILLAGE_CUSTOM_BASE_URL` 覆盖。仅接受 HTTPS；不跟随跳转。支持 `max_tokens` 或 `max_completion_tokens` 字段，按服务实际兼容要求选择。

“元宝”是聊天产品；这个原型不读取元宝登录态、Cookie 或账号令牌。腾讯开发者模型可按自己账号已开通的混元/TokenHub API 配置，不能将它描述为元宝应用 API。新开通账号与已有混元账号端点可能不同，以当前控制台为准。

参数参考（2026-11-16核对，未进行真实付费调用）：[DeepSeek](https://api-docs.deepseek.com/quick_start/agent_integrations/)、[方舟 OpenAI 兼容](https://docs.volcengine.com/docs/ark/compatible-with-openai-sdk?lang=en)、[百炼 Chat](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions/)、[腾讯 TokenHub](https://cloud.tencent.com/document/product/1823/132252)。地域、模型、账号权限和账单由各服务商决定。

## 粮仓记账约定

`可用额度 = max(0, 分配额度 - 已确认实际用量 - 仍占用的预留额)`。

调用前按 UTF-8 字节、消息开销与输出上限进行保守预留，**这是启发式预算，不能声称与所有服务商分词完全一致或保证账单硬上限**。仅收到合法的服务商 `usage.prompt_tokens/completion_tokens/total_tokens` 后，才用实际合计替换预留；合计可以包含服务商计入的推理用量。若实际超过预留，会照实扣账并显示超额。

请求超时、返回缺少 usage、进程重启后结果未知，都保留预留额度并标记“待核对”，不按零用量退款、不自动重试。首版尚无账单核销界面，需核对后再做核销功能。不同厂商 Token 价格不同，粮仓不是费用排行榜。居民耗尽预算会停止新模型调用；本地行走与日常仍可继续。

## 美术

点击议事厅会进入独立的圆桌会议室地图，村民有12个不同座位。下方“会议记录”查看历史提问和完整发言；“新的议题”建立草稿并选择参与者，支持1–12位居民。“村民发言气泡”只显示选中会议已有的真实发言，尚未发言时明确显示候会；点击气泡可读全文。会议室不叠加室外雨滴、云影与雾气。

“地图与建设 / 世界提案”接入首版世界治理。AI自主思考可提出已有建筑建设、东林开拓、林间小屋/菜园/瞭望台建设，或调整劳动周期、收获量和休息时长。每位已连接居民独立调用模型投票，需要全体居民过半数同意；未连接的居民不能由程序代投。通过后重新检查资源、占地与入口，扣材料并执行一次；变更前存档保存在 `data/world-history/`，票据与世界版本可追溯。东林有独立生图地图、三处建设空地、四向寻路、居民实际前往施工与采集回村，建筑图像缩放在碰撞占地内，绘制按脚底高度排序。首版是受验证的指令目录，尚不是任意程序生成地图、建筑或代码的编辑器；更多区域和指令需持续扩展实现。

新美术通过ChatGPT内置生图制作：`web/assets/maps/council-hall-v1.png`（圆桌会议室）、`web/assets/maps/eastwood-v1.png`（东林空地）、`web/assets/props/waterwheel-front-v1.png`（透明水车轮盘）。原地图保留；`world-scenes.js`、`living-props.js` 把人物、气泡、机械转动与施工叠加到背景，不把文本或角色画死在图片里。生成记录和验证见工作区 `work/token-village-world-20261117-r1/`。

AI也可以选择巡查：结合自己的理由触发确定性的建筑占地、入口通行与资源检查，结果在世界提案页面的“居民巡查”中保留。该报告检查的是已实现的世界约束，不代表AI已经审计或修复全部程序漏洞。

小镇天气由 `web/climate.js` 驱动，支持晴天、多云、细雨、薄雾。自动模式按存档中的村庄时间每4小时切换时段，前20分钟渐变；天气安排可复现，刷新不会重新随机抽取。点击左上角天气牌打开选择窗口，可以手动固定天气，偏好保存在本浏览器；“随村庄变化”恢复自动。场景包含云影、冷暖光线、斜雨、河面涟漪、石板路积水和沿溪流动的雾。樱花受风影响，雨雾中减少蝴蝶；所有运动与过渡跟随可暂停的视觉时钟。首版天气不改变产量、寻路或Token，不调用外部天气服务或模型API。

`web/living-props.js` 把水车的轮辐、轮缘接头、固定轮轴、前景水流与飞溅分别绘制：轮盘18秒转一圈，磨坊屋顶与支架保持固定，水流盖在轮盘前面。运动采用同一视觉时钟，暂停时轮盘和水滴同时停下。原地图图片保持不变，机械活动部分在实际世界坐标中绘制，缩放与拖动不会使组件脱离建筑。

地图使用有边界的游戏镜头（`web/map-camera.js`），最远视角按窗口比例铺满场景，不再将全村缩成露出纯色底的居中图片。滚轮以鼠标位置为中心平滑缩放，拖拽始终限制在地图范围内；手机支持双指缩放和移动。房子图标是“回到村心”，不会切换到带边框的全景。地图获得焦点时也可用方向键移动、Home回到村心。不同宽高比会裁去部分场景，可拖动查看，不拉伸美术。

窗口与HUD已接入木框纸面皮肤：`web/assets/ui/village-kit-v2.png` 从新UI组件参考整理而来，31个窗口、标题牌、按钮、输入框和头像框区域由 `ui-skin-v2.json` 定义；`ui-skin.js` 缓存组件，`wood-ui.css` 使用九宫格适配实际内容。建筑窗口只保留一个名称标题，并显示当前场景小图；登记册保留六款外观选择，窄屏可滚动且关闭按钮独立可见。
